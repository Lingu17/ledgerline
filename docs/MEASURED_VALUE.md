# Measured value on synthetic companies

**Synthetic data only.** These are made-up companies, not customers. They show what the rules decide on their own for this mix of payments; a real company's mix will differ, and only a pilot can measure real time saved.

200 synthetic companies (seeds 1–200, the same ones the [accuracy run](ACCURACY_REPORT.md) checks), 8,826 payments, in 549 s. Generated by `scripts/measure_value.py`. For each payment it reads the **first plan the rules made**, before any person acted. Automatic asking of payer agents is switched off here, as in the accuracy run, so no payer agent answered.

The generator makes hard cases on purpose, so these shares are lower than a tidy company's would be: of the payments it generated, 2,960 had no reference at all (1,663 of them for exactly an open invoice's balance, which must never be matched on amount alone), 439 looked like duplicates, 555 were overpayments and 562 came from unknown payers.

| First plan | Payments | Share | What it was |
|:--|--:|--:|:--|
| Closed with no person | 1,505 | 17.1% | clean match 1,236, clean with fee 269 |
| Decided with no person, still open | 1,174 | 13.3% | partial payment 1,174: applied, the rest is a balance request |
| Waiting for the payer's agent | 1,694 | 19.2% | unknown reference 1,029, apparent duplicate 259, overpayment 231, unknown invoice 175: customers with a registered agent; a person decides if it cannot answer |
| Escalated to a person, with its reason | 4,453 | 50.5% | unknown reference 2,101, overpayment 478, apparent duplicate 474, reference conflict 445, unidentified payer 392, wrong currency 302, unknown invoice 261 |

- **Decided with no person: 2,679 of 8,826 (30.4%).**
- **Refunds sent without verified evidence or a person: 0.** Every apparent duplicate and overpayment was held (asked about, or escalated) instead of refunded. Refund approvals created: 0.
- **Hours of matching saved, if each payment takes 5 minutes by hand: 223 hours** across the 200 companies, about 1.1 hours each. The 5 minutes is an assumption, not a measurement; the hours scale with it.

## Wrong refunds avoided

No payer agent answers in this synthetic run, so it cannot show a refund being dropped. The reference company shows it: DEP-1005 looks like a second payment of a paid invoice, so the rules propose a refund; the payer's agent answers with a signed claim that it is an advance, all three checks pass, and the refund is dropped before any money moves (identical in all 25 walkthroughs of the [accuracy run](ACCURACY_REPORT.md)). That is one case, not a rate.

## What this does not measure

- How often real payer agents exist and answer, and how often their answers pass the three checks.
- A real company's payment mix, which decides the shares above.
- Time actually spent per payment, which the minutes assumption stands in for.
